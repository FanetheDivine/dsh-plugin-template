# Feature Specification: Serena 符号查询

**Feature Branch**: `feat/006-serena-symbol-cli`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "模仿 dsh-plugin-om 增加 Serena"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查询代码符号 (Priority: P1)

维护者通过统一的开发命令查找符号定义、引用、签名和文档，减少全文搜索后的手工筛选。

**Why this priority**: 符号查询是本需求的核心价值，三个只读查询可独立交付使用。

**Independent Test**: 在包含多个同名符号的 TypeScript 项目中分别执行定义、引用和文档查询，检查返回目标、引用位置及签名文档。

**Acceptance Scenarios**:

1. **Given** 项目中存在唯一符号， **When** 维护者按完整名称查询定义， **Then** 返回该符号的定义位置。
2. **Given** 项目中存在被其他文件引用的符号， **When** 维护者查询引用， **Then** 返回项目内全部已识别引用及其位置。
3. **Given** 符号包含签名和文档， **When** 维护者查询文档， **Then** 返回对应签名和注释。
4. **Given** 名称对应多个候选符号， **When** 维护者按名称查询， **Then** 命令拒绝猜测并列出可区分的候选。
5. **Given** 维护者知道目标文件和声明行， **When** 使用位置限定查询， **Then** 命令只解析该声明符号。
6. **Given** 维护者只提供文件位置， **When** 执行查询， **Then** 返回带声明行的文件符号候选。

---

### User Story 2 - 获得一致且完整的工程结果 (Priority: P2)

维护者在 TypeScript 和 JavaScript 混合项目中获得统一的路径、行号和工程引用结果，文件在外部修改后仍能查询最新内容。

**Why this priority**: 结果完整性和稳定格式决定查询能否用于日常开发与自动化检查。

**Independent Test**: 在含工程引用、松散 JavaScript 文件和外部文件修改的夹具上执行引用查询，检查覆盖范围、输出格式与刷新结果。

**Acceptance Scenarios**:

1. **Given** 查询结果包含路径和行号， **When** 命令输出结果， **Then** 路径统一使用 `/`，行号从 1 开始。
2. **Given** 项目包含 TypeScript 工程配置， **When** 查询引用， **Then** 命令识别工程成员并覆盖相关工程。
3. **Given** 项目包含未列入工程配置的 JavaScript 文件， **When** 查询引用， **Then** 命令补全可识别的松散文件引用。
4. **Given** 文件被外部进程修改， **When** 发起下一次查询， **Then** 查询使用修改后的内容。
5. **Given** 引用结果为空， **When** 查询完成， **Then** 返回空结果且不重复执行查询。
6. **Given** 工程初始化失败或查询超时， **When** 查询终止， **Then** 返回明确错误。

---

### User Story 3 - 管理项目查询实例 (Priority: P3)

维护者安装依赖后即可使用查询能力，可查看或停止当前项目的后台实例，也可选择单进程查询。

**Why this priority**: 实例复用降低重复查询等待时间，生命周期命令保证 worktree 可安全清理。

**Independent Test**: 连续执行查询并检查实例状态，再停止实例；分别验证并发调用、空闲退出、单进程模式和启动失败回退。

**Acceptance Scenarios**:

1. **Given** 开发环境满足前置要求， **When** 安装项目依赖， **Then** 查询依赖自动准备完成。
2. **Given** 当前项目没有运行实例， **When** 发起默认查询， **Then** 创建当前项目专属实例并完成查询。
3. **Given** 当前项目已有运行实例， **When** 再次查询， **Then** 复用该实例。
4. **Given** 实例默认空闲达到 15 分钟， **When** 没有新的查询， **Then** 实例自动退出。
5. **Given** 维护者设置合法空闲秒数， **When** 实例运行， **Then** 按该时长退出。
6. **Given** 维护者请求状态或停止， **When** 执行对应命令， **Then** 只查看或停止当前项目的实例。
7. **Given** 维护者选择单进程模式， **When** 执行查询， **Then** 查询不依赖后台实例。
8. **Given** 后台实例启动失败， **When** 查询尚未提交， **Then** 提示故障并回退到单进程，且查询至多执行一次。
9. **Given** 两个项目或多个并发查询同时运行， **When** 各自执行命令， **Then** 实例状态、访问凭据和查询结果保持隔离。
10. **Given** 维护者准备删除 worktree， **When** 停止并确认当前项目实例退出， **Then** 可清理该 worktree。

### Edge Cases

- 符号名称不存在时返回明确错误。
- 同名符号存在歧义时返回候选，不选择任意目标。
- 文件位置缺少行号时返回符号候选，行号非法时拒绝查询。
- 输出超过长度上限时保留截断说明，路径和行号仍保持统一格式。
- 实例状态文件损坏或脚本内容变化时替换旧实例状态。
- 停止请求只清理匹配的目标实例，避免误删新实例状态。
- Windows 后台启动不弹出控制台。
- 环境变量不是正数时返回明确配置错误。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目 MUST 提供 `definition`、`references` 和 `doc` 三个只读符号查询命令。
- **FR-002**: 三个查询命令 MUST 支持按符号名称或文件位置定位目标，两种定位方式互斥。
- **FR-003**: 文件位置 MUST 支持可选的 1 起始声明行，并在省略行号时返回文件符号候选。
- **FR-004**: 查询 MUST 对无匹配和多匹配给出可操作的错误，多匹配包含候选名称和位置。
- **FR-005**: 查询结果 MUST 使用 `/` 路径分隔符和 1 起始行号。
- **FR-006**: 查询命令 MUST 支持正整数输出长度上限，并保留截断说明。
- **FR-007**: 引用查询 MUST 识别 TypeScript 工程成员、工程引用和可识别的松散 JavaScript 引用。
- **FR-008**: 每次查询 MUST 同步外部文件修改，空引用结果 MUST 直接返回。
- **FR-009**: 默认查询 MUST 复用当前项目专属后台实例，不同项目的实例 MUST 隔离。
- **FR-010**: 后台实例 MUST 提供状态查看与停止命令，并默认在空闲 15 分钟后退出。
- **FR-011**: 用户 MUST 能通过环境设置调整空闲时长、禁用后台实例或隔离实例状态。
- **FR-012**: 后台实例启动失败时 MUST 提示并回退到单进程，已提交查询 MUST 不重复执行。
- **FR-013**: 并发启动、停止和查询 MUST 串行化实例变更，避免损坏状态或误停其他实例。
- **FR-014**: 后台通信 MUST 验证当前实例凭据，并限制请求大小。
- **FR-015**: 依赖安装 MUST 自动准备固定版本的查询依赖，并提供手动准备命令。
- **FR-016**: 开发文档 MUST 说明前置要求、查询方式、实例管理和 worktree 清理步骤。
- **FR-017**: Agent 指引 MUST 要求优先使用符号查询完成定义、引用和文档检索。
- **FR-018**: 本需求 MUST 归类为模板变更，保留现有插件入口、`demo_echo`、用户文档和测试行为。

### Key Entities

- **符号查询**: 查询类型、符号名称或文件位置、输出长度上限及标准化结果。
- **项目实例**: 所属项目、进程标识、连接信息、访问凭据、构建标识和空闲期限。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 定义、引用和文档三类查询在标准夹具上的有效请求成功率达到 100%。
- **SC-002**: 所有返回位置的路径分隔符和 1 起始行号符合约定，自动化格式检查通过率达到 100%。
- **SC-003**: 工程引用与松散 JavaScript 引用夹具中的预期引用召回率达到 100%。
- **SC-004**: 同一项目连续两次查询只保留一个后台实例，不同项目并发查询不会混用实例。
- **SC-005**: 默认实例在 15 分钟空闲后退出，自定义空闲时长和停止命令均可通过自动化验证。
- **SC-006**: 后台启动失败回退、并发启动、状态损坏和外部文件修改场景均通过自动化回归。
- **SC-007**: 现有模板插件测试保持全部通过，`demo_echo` 行为无回归。

## Assumptions

- 参考 `dsh-plugin-om` 当前 Serena 能力的用户可见行为。
- 本需求只增加开发期能力，不向 DSH 会话注册 Serena 工具或 MCP 服务。
- 维护者已安装 uv、Node.js 和受支持的 Python，并能在首次准备时获取依赖。
- 第一阶段聚焦 TypeScript、JavaScript 和相关模块文件。
- 查询只读取项目内容，实例状态与日志存放在用户级目录，不写入发布包。
