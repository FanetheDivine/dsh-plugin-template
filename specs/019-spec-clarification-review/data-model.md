# 数据模型：两段访谈与审查门禁

## 待确认决策

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 编号 | 当前访谈内的稳定标识 | 用户按编号回答 |
| 问题 | 需要用户决定的具体事项 | 依赖满足后才能进入当前批次 |
| 推荐答案 | Agent 推荐的选择 | 附理由 |
| 依赖 | 前置决策编号 | 未满足时保留在待确认列表 |
| 状态 | 未问、已问未答或跳过 | 回答后从待确认列表移除 |

待确认决策保存在对应 `spec.md` 或 `plan.md`，支持跨会话继续访谈。

## 澄清记录

每条记录包含会话日期、稳定编号、完整问题与最终答案。答案写回时同步更新受影响需求、计划、数据或验证内容，移除被取代的矛盾描述。

## 审查记录

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 日期 | 用户作出决定的日期 | ISO 日期 |
| 决定 | `Approved` 或 `Waived` | 针对当前完整文档 |
| 适用范围 | 被批准的文档与当前完整版本 | 部分认可不构成批准 |
| 未确认事项 | 豁免时仍未解决的决策 | 豁免时完整列出 |
| 风险 | 未确认事项的影响 | 豁免时必填 |

审查记录采用追加方式保留历史。文档顶部的状态字段表示当前状态。

## 状态转换

1. `Draft`：探索与访谈进行中，或当前完整版本尚未审查。
2. `Approved`：用户批准当前完整规格或计划。
3. `Waived`：用户明确豁免当前环节，未确认事项与风险已记录。
4. 实质修改后回到 `Draft`；纯排版修正保持原状态。
5. 规格回到 `Draft` 时暂停下游计划与任务；计划回到 `Draft` 时暂停任务与实现。

## 完整性约束

- 进入计划前，规格状态必须为 `Approved` 或 `Waived`，且待确认决策均为空或已豁免。
- 进入任务前，规格和计划均满足上述条件。
- 进入实现前不得存在未豁免的待确认决策。
