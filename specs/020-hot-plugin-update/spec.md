## 用户场景与测试

### 用户故事 1 - 重建后运行中的实例加载新插件（优先级：P1）

维护者保持一个运行中的 web profile 实例，在仓库里修改插件代码并重新构建。实例中的插件按新代码工作，前端界面同步更新，宿主进程与会话继续可用，不需要重新安装插件或重启 GUI。

**优先级理由**：每次改动都要重装并重启，实机验证的迭代成本高于编写代码本身，长会话也会被中断。

**独立测试**：启动实机 GUI 并在会话中触发插件行为；修改插件代码并构建；再次触发同一行为，观察结果按新代码变化，界面无需刷新，宿主进程号与会话保持不变。

**验收场景**：

1. **Given** web profile 实例正在运行且插件已加载，**When** 仓库构建成功，**Then** 插件在数秒内按新代码工作，宿主进程不重启。
2. **Given** 实例中有进行中的会话，**When** 插件热更新完成，**Then** 会话历史、工作区与连接保持可用。
3. **Given** 前端产物被重新构建，**When** 热更新完成，**Then** 已打开的页面显示新前端行为，无需手动刷新。
4. **Given** 构建失败，**When** 维护者再次触发插件行为，**Then** 旧代码继续工作，失败原因可见。

---

### 用户故事 2 - skill 指导模型在运行实例中迭代（优先级：P2）

Agent 按实机 skill 操作时，在已启动的实例上「改代码 → 构建 → 观察 → 重跑用例」，不再执行重装插件或重启宿主。启动脚本保持现有用法，一次实机轮次只在开始时启动。

**优先级理由**：模型按 skill 执行；skill 若仍写重装与重启步骤，热更新链路不会被用到。

**独立测试**：按更新后的 skill 完成一次插件改动，检查步骤中是否出现重装命令或重启宿主，并确认改动在同一实例中可见。

**验收场景**：

1. **Given** 实机实例已启动，**When** Agent 修改插件代码并构建，**Then** Agent 在技能文档给出的同一实例中观察新行为。
2. **Given** skill 需要启动实例，**When** Agent 执行启动步骤，**Then** 命令与现状一致，不引入复用识别或接管逻辑。
3. **Given** 宿主或插件配置变更，**When** Agent 按 skill 操作，**Then** 沿用已有的配置热重载说明。

---

### 用户故事 3 - 装载校验与文档同步（优先级：P3）

实机测试的装载用例校验宿主加载的产物就是仓库构建产物。skill 说明链接安装、HMR 生效范围、每轮清理与打包校验的处置，避免模型按旧流程重装。

**优先级理由**：热更新让「加载源」与「打包产物」分离，缺少校验会掩盖加载了旧代码的情况。

**独立测试**：重建仓库产物后运行装载用例，确认用例通过；按 skill 步骤完成一次迭代，确认不含重装与重启。

**验收场景**：

1. **Given** 插件以链接方式安装，**When** 运行装载用例，**Then** 用例确认加载产物与仓库 `dist` 一致且版本相同。
2. **Given** 维护者按更新后的 skill 操作，**When** 完成一次迭代，**Then** 步骤中不出现重装插件或重启宿主。
3. **Given** 一轮实机测试结束，**When** 维护者执行清理步骤，**Then** profile 被删除，下一轮重新搭建。

### 边界情况

- 构建产物被删除或损坏：实例保留已加载的代码，skill 说明恢复步骤。
- 热替换导入失败：插件进入失败状态并给出可见错误，再次构建修正后自动恢复。
- 实机 profile 在每轮结束后删除，下一轮重新搭建；旧 profile 不兼容。
- 维护者在热更新期间发送消息：会话不中断，下一次插件调用使用新代码。
- 宿主升级后 HMR 配置项或链接行为变化：装载用例与 skill 给出与版本相关的说明。
- 修改只发生在 `src` 未重新构建：实例行为不变；skill 要求构建后再观察。

## 需求

### 功能需求

- **FR-001**: 实机搭建 MUST 以链接方式安装被测插件，让宿主加载的产物就是仓库当前的构建产物。
- **FR-002**: 实机 profile MUST 启用 HMR 并监听仓库 `dist`。
- **FR-003**: 仓库构建成功后，运行中的 web profile 实例 MUST 加载新插件代码并生效，无需重启宿主进程或重新安装插件。
- **FR-004**: 热更新 MUST 保留宿主进程、会话、工作区与页面连接；插件实例按新代码重新挂载。
- **FR-005**: 前端产物重建后 MUST 在同一页面自动更新，不依赖维护者刷新。
- **FR-006**: 热更新失败 MUST 在界面或日志中可观察，并在再次构建成功后自动恢复。
- **FR-007**: 启动脚本的用法与行为 MUST 保持不变；本次改动不引入实例复用识别或接管逻辑。
- **FR-008**: 装载用例 MUST 校验宿主加载的产物与仓库构建产物一致；不处理按打包副本安装的旧实例。
- **FR-009**: 实机 skill MUST 改为「改代码 → 构建 → 观察 → 重跑用例」的迭代流程，明确不再重装与重启，并说明前端自动更新。
- **FR-010**: skill MUST 说明运行实例的保持方式：一次实机轮次只在开始时启动实例，后续迭代复用该实例；轮次结束时删除 profile。
- **FR-011**: 文档 MUST 说明热更新的边界：配置热更、前端产物、宿主版本升级、打包安装校验的去留与 profile 清理。

### 关键实体

- **web profile 实例**：一个运行中的宿主进程，持有会话、工作区、插件加载图与热更新通道。
- **插件加载源**：宿主实际导入的产物位置；链接安装下即仓库 `dist`。
- **热更新事件**：构建产物变化触发的一次插件替换，带成功或失败结果。
- **实机 profile**：搭建脚本生成的隔离配置、链接安装记录与测试驱动脚本集合。

## 成功标准

### 可衡量结果

- **SC-001**: 「改源码 → 构建 → 在 GUI 观察」一次循环在一个构建周期内完成，不含重装命令与宿主重启。
- **SC-002**: 连续三次构建后，同一实例仍可完成一次插件调用，会话与工作区数量不变。
- **SC-003**: 按 skill 走完一次迭代，步骤中重装与重启宿主出现次数为 0。
- **SC-004**: 装载用例在链接安装下通过，并在重建产物后仍判定一致。

## 假设

- 宿主 `0.2.2-rc.3` 的 HMR 服务可在 web profile 上启用并监听仓库 `dist`。
- 探索结论：`@deepseek-ai/dsh-base` 在 launcher 提供 `profileContext` 时启用 `hmr` 条目，`root` 默认空，补丁可改写。
- 探索结论：`@deepseek-ai/dsh-hmr` 支持替换「链接包的目标文件」，`node_modules` 下的安装副本不会因文件变化触发重载。
- 探索结论：`@deepseek-ai/dsh-client-hmr` 每 500 毫秒轮询每个客户端产物并推送重建帧，前端可免刷新替换。
- 维护者环境为 Windows + Git Bash + 本机 Chrome，脚本沿用现有环境。
- 构建由 `pnpm build` 或 `pnpm dev` 产生 `dist/`，实机搭建前仓库已构建完成。
- 实机测试仍只读插件代码；验证热更新所需的临时改动在报告与提交中说明。
