# 国际化

插件文案分两处：`locale/*.json` 供宿主在插件未激活时读取插件标题与描述，`src/client/locales.ts` 供浏览器渲染界面文案。两处都由宿主的 locale 服务解析。

## 元数据资源

| 文件 | 内容 |
| --- | --- |
| `locale/zh.json` | 中文标题与描述 |
| `locale/en.json` | 英文标题与描述 |

`meta` 字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `meta.title` | 是 | 插件行与详情页的标题，单行 |
| `meta.description` | 是 | 能力、用法与限制 |
| `meta.detail` | 否 | 详情页文档路径，指向包内 Markdown；省略时详情页使用 `README.md` |

规则：

- 宿主按当前语言取文件；缺该语言时沿回退链取下一份，最终回落 `en`。
- 缺 `meta.title` 或 `meta.description` 时回落 `package.json` 的 `name` 与 `description`。
- 资源文件必须导出并打进包，声明见下节。

## 包清单声明

```json
{
  "exports": { "./locale/*.json": "./locale/*.json" },
  "files": ["dist", "cordis.patch.yml", "locale/*.json", "README.md"]
}
```

漏掉 `exports` 时宿主读不到元数据；漏掉 `files` 时发布包缺文件。

## 前端字典

- 命名空间为 `dsh-plugin-template`，字典在 `src/client/locales.ts`，中文字典是键集事实源。
- `apply` 里注册：`ctx.locale.register(NS, { zh, en })`，中英文键集必须一致。
- 槽位注册传 `locale: NS`，组件通过注入的 `t` 取文案。
- 槽位之外的文案用 `ctx.locale.bind(NS)`。
- 键名并入 `LocaleNamespaceMap`，缺失的键在编译期报错。

## 语言与回退

- 用户在 Settings → General → Language 选择语言，选择写入宿主设置并跨浏览器生效。
- 未选择时按浏览器语言匹配已注册语言，匹配失败回落 `en`。
- 查找顺序：当前语言 → 该命名空间 → `common` 命名空间 → 键名。
- 切换即时生效，`<html lang>` 同步更新；注册时捕获的文案保持注册时的语言。

## 文案规则

- 占位符写作 `{name}`，译文保留同名占位符。
- 斜杠命令与 API 字段名保持原文。
- 资源文件不得含零宽空格 U+200B 与 BOM U+FEFF。
- 英文标题用 sentence case，只大写首词与专有名词。

## 新增一种语言

1. 复制 `locale/en.json` 为 `locale/<id>.json`，翻译 `meta.title` 与 `meta.description`。
2. 语言 id 不在宿主内置集合内时，先由语言包调用 `ctx.locale.addLanguage({ id, label, fallback: 'en' })`。
3. 在 `src/client/locales.ts` 增加同键集字典，并加入注册调用。
4. 更新 `tests/metadata.test.ts` 的基线列表与 `tests/client.test.ts` 的字典断言。
5. 运行 `pnpm format && pnpm check`。

## 校验

| 命令 | 检查 |
| --- | --- |
| `pnpm vitest run tests/metadata.test.ts` | 结构、键集、禁用字符与清单声明 |
| `pnpm check` | 类型、lint、测试与构建 |
| `npm pack --dry-run --json` | 发布内容包含全部 `locale/*.json` |

实机核对：在“插件”页切换语言，核对模板插件的标题与描述随之变化，停用状态下照常显示。
